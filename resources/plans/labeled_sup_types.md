# Labeled SUP/DUP + Types for Interaction Net Search

## Status: PLANNING

## Motivation

TinyHVM's SUP/DUP pairs are currently **unlabeled** — EXT field hardcoded to 0 in both
`thvm_sup` and `thvm_dup`. All DUP-SUP interactions unconditionally annihilate (take branch
by index). This prevents:

1. **Nested search spaces** — two overlapping SUPs clobber each other without labels
2. **Collapse monad** — label-aware extraction (pairwise vs Cartesian) impossible
3. **Type-directed pruning** — no mechanism to prune superposed branches by type constraints
4. **Correct duplication through SUPs** — `DUP_L(SUP_M(...))` with L≠M must commute, not annihilate

## HVM4 Reference (as of 2026-03-28)

### Term encoding

HVM4 uses the same 64-bit packed word as TinyHVM:
```
| SUB (1 bit) | TAG (7 bits) | EXT (18 bits) | VAL (38 bits) |
```

HVM3 used 16-bit labels in a dedicated field. HVM4 stores labels in the EXT field (18 bits =
262,144 labels). TinyHVM already has this layout — no encoding changes needed.

### HVM4 tag set (45+ tags)

HVM4 has grown far beyond the core IC:
```
APP=0, VAR=1, LAM=2, DP0=3, DP1=4, SUP=5, DUP=6, ALO=7, REF=8, NAM=9,
DRY=10, ERA=11, MAT=12, C00-C16=13-29, NUM=30, SWI=31, USE=32, OP2=33,
DSU=34, DDU=35, EQL=36, AND=37, OR=38, UNS=39, ANY=40, INC=41,
BJV=42, BJ0=43, BJ1=44, PRI=45
```

Key new tags for us:
- **DSU/DDU** (Dynamic SUP/DUP): label is a runtime expression, reduced to NUM before creating normal SUP/DUP
- **INC**: Priority wrapper — decreases priority in collapse work-stealing queue
- **ANY**: Wildcard that duplicates itself and equals anything
- **EQL**: Structural equality, strict on both sides
- **ALO**: Lazy allocation — book terms instantiated on demand, not eagerly cloned
- **DRY**: Stuck application (head-normal but irreducible)
- **BJV/BJ0/BJ1**: Quoted de Bruijn variables for collapse readback

### Core IC interaction rules (exact from VictorTaelin/Interaction-Calculus)

```
APP-ERA:  (* a)              → *
APP-LAM:  (λx.f a)           → x ← a; f
APP-SUP:  (&L{a,b} c)        → !&L{c0,c1}=c; &L{(a c0),(b c1)}

DUP-ERA:  !&L{r,s} = *       → r←*; s←*
DUP-LAM:  !&L{r,s} = λx.f    → r←λx0.f0; s←λx1.f1; x←&L{x0,x1}; !&L{f0,f1}=f
DUP-SUP:  !&L{x,y} = &L{a,b} → x←a; y←b                              (annihilation)
DUP-SUP:  !&L{x,y} = &R{a,b} → x←&R{a0,b0}; y←&R{a1,b1};            (commutation)
                                 !&L{a0,a1}=a; !&L{b0,b1}=b
```

### Critical invariant: labels are NEVER freshly generated by interactions

Commutation preserves both the DUP label AND the SUP label. New DUP nodes get the
original DUP label `L`. New SUP nodes get the original SUP label `R`. No interaction
rule creates a fresh label. Labels are assigned at construction time (parse time in
HVM4, `thvm_fresh_label` in TinyHVM) and propagated through interactions.

This is why `thvm_fresh_label` is only called when *building* the search space, never
inside the interaction handler.

### APP-SUP: DUP label matches the SUP label

This is critical and my earlier draft was ambiguous. From HVM4's `wnf_app_sup`:

```c
fn Term wnf_app_sup(u64 app_loc, Term sup, Term arg) {
    u64 sup_loc = term_val(sup);
    u32 lab = term_ext(sup);           // <-- use the SUP's label
    Copy D = term_clone(lab, arg);     // <-- DUP arg with SAME label
    // ...
    return term_new_sup_at(app_loc, lab, ap0, ap1);
}
```

The DUP of the argument uses **the SUP's label**, not a fresh one. This ensures that
if arg itself contains a SUP with the same label, the DUP-SUP annihilation will fire
correctly (the arg's copy will track the same search dimension).

### DUP-NOD: generic duplication for compound nodes

HVM4 handles ALL compound nodes (CTR, MAT, OP2, TOP) with a single generic rule:

```c
fn Term wnf_dup_nod(u32 lab, u64 loc, u8 side, Term term) {
    u32 ari = term_arity(term);
    if (ari == 0) { return term; }  // atoms just copy
    for (u32 i = 0; i < ari; i++) {
        Copy A = term_clone_at(t_loc + i, lab);
        heap_set(r0_loc + i, A.k0);
        heap_set(r1_loc + i, A.k1);
    }
    Term r0 = term_new(0, t_tag, t_ext, r0_loc);
    Term r1 = term_new(0, t_tag, t_ext, r1_loc);
    return heap_subst_cop(side, loc, r0, r1);
}
```

This means DUP through a TAG_TOP creates two copies of the TOP node, each with its
own DUP'd arguments. For TinyHVM this is the DUP-TOP rule: duplicating a lazy tensor
op creates two independent lazy ops with DUP'd inputs.

### DUP-SUP commutation (exact HVM3 C code)

```c
Term reduce_dup_sup(Term dup, Term sup) {
    Loc dup_loc = term_loc(dup);
    Lab dup_lab = term_lab(dup);
    Lab sup_lab = term_lab(sup);
    Loc sup_loc = term_loc(sup);
    if (dup_lab == sup_lab) {
        // ANNIHILATION
        Term tm0 = got(sup_loc + 0);
        Term tm1 = got(sup_loc + 1);
        if (term_tag(dup) == DP0) {
            sub(dup_loc + 0, tm1);  // other projection gets tm1
            return tm0;
        } else {
            sub(dup_loc + 0, tm0);
            return tm1;
        }
    } else {
        // COMMUTATION — 4 new nodes, labels preserved exactly
        Loc loc = alloc_node(4);
        set(su0 + 0, term_new(DP0, dup_lab, du0));  // dup_lab preserved
        set(su0 + 1, term_new(DP0, dup_lab, du1));
        set(su1 + 0, term_new(DP1, dup_lab, du0));
        set(su1 + 1, term_new(DP1, dup_lab, du1));
        if (term_tag(dup) == DP0) {
            sub(dup_loc + 0, term_new(SUP, sup_lab, su1));  // sup_lab preserved
            return term_new(SUP, sup_lab, su0);
        } else {
            sub(dup_loc + 0, term_new(SUP, sup_lab, su0));
            return term_new(SUP, sup_lab, su1);
        }
    }
}
```

### DSU/DDU: Dynamic (runtime-computed) labels

HVM4 adds `DSU` and `DDU` for labels that are expressions rather than constants:

```c
// DSU: &(label_expr){a, b} — reduce label_expr to NUM, then make SUP
fn Term wnf_dsu_num(Term lab_num, Term a, Term b) {
    u32 lab = term_val(lab_num);
    return term_new_sup(lab, a, b);
}

// DDU: !&(label_expr){x} = val; bod — reduce label_expr, then clone
fn Term wnf_ddu_num(Term lab_num, Term val, Term bod) {
    u32 lab = term_val(lab_num);
    Copy V = term_clone(lab, val);
    return APP(APP(bod, V.k0), V.k1);
}
```

This enables computed search spaces where the label itself depends on data.

### Unordered superpositions (HVM3, not yet confirmed in HVM4)

Unordered SUP `%L{x,y}` satisfies `%L{x,y} == %L{y,x}`. The corresponding unordered
DUP `!%L{x}=v` has a **single** output port (both ports merged). Key properties:

- UDUP is **never consumed** — acts as an infinite ref-counted producer
- Solves O(n²) DUP chain accumulation (redundant chains collapse)
- UDUP-USUP with matching labels: `!%L{x} = %L{a,b}` → `!%L{x}=b; a` (consume ONE branch)
- UDUP-USUP with different labels: standard commutation

This is relevant to TinyHVM's tensor sharing: when a tensor is used N times in a
computation graph, unordered DUP gives O(1) access instead of O(N) chain traversal.
However, HVM4's current public code doesn't show unordered nodes yet.

### Collapse monad (exact algorithm)

The Collapse monad flattens superposed values. Same-label = pairwise, different-label = Cartesian.

```haskell
data Collapse a = Sup Int (Collapse a) (Collapse a) | Val a

bind :: Collapse a -> (a -> Collapse b) -> Collapse b
bind a f = fork a (repeat id) where
  fork (Val v)     paths = pass (f v) (map (\x -> x E) paths)
  fork (Sup k x y) paths = Sup k (fork x (mut k putO paths))
                                  (fork y (mut k putI paths))
  pass (Val v)     _     = Val v
  pass (Sup k x y) paths = case paths !! k of
    E   -> Sup k x y              -- unseen label: keep (Cartesian)
    O p -> pass x (mut k (\_->p) paths)  -- seen left: follow left (pairwise)
    I p -> pass y (mut k (\_->p) paths)  -- seen right: follow right (pairwise)
```

**How it works:**
1. `fork` phase: walk the first Collapse tree. At each `Sup k`, record which branch was
   taken (O=left, I=right) as a bit-string indexed by label `k`.
2. `pass` phase: after hitting `Val v`, apply `f v` to get the second tree. Walk it.
   At each `Sup k`, check the recorded path for label `k`:
   - If `O p`: follow left (pairwise merge — same dimension, same choice)
   - If `I p`: follow right
   - If `E`: label not seen → keep the Sup (Cartesian product of independent dimensions)
3. `flatten`: DFS concatenation of all `Val` leaves.

HVM4's production version uses a **priority queue** for flattening (not DFS):
- `INC` nodes decrease priority (explored later)
- Work-stealing across threads for parallel collapse
- BFS/PQ ordering ensures breadth-first search of the result space

### ICC: Interaction Calculus of Constructions (Taelin, 2025)

Types are encoded with two new primitives:

```
θx. term    — Bridge (dual of lambda)
{term:type} — Annotation
```

Core type encodings:
```
Fun = λA λB θf λx {(f {x: A}): B}           -- simple function type
All = λA λB θf λx {(f {x: A}): (B x)}       -- Pi type (dependent function)
Ind = λA λB θf λx {(f {x: A}): (B f x)}     -- inductive/self type
Sig = λA λB θp {(p {p.0: A} {p.1: (B p.0)})} -- Sigma type (dependent pair)
```

Type checking = interaction net reduction. An ill-typed term hits a contradiction during
reduction, naturally pruning it from the superposition. The bridge node binds a variable
that flows in the *opposite* direction from lambda — enabling type information to flow
backward through the net.

Status: ICC is "still new and many aspects are not clear" per Taelin. The repo has
incomplete documentation.

### 1c. DUP-SUP interaction with label check

Following HVM3's exact implementation:

```c
case TAG_DP0:
case TAG_DP1: {
    u32 dp_index = (tag == TAG_DP1) ? 1 : 0;
    u32 dup_label = term_ext(t);
    u64 dup_loc = term_val(t);
    Term val = thvm_reduce(ctx, heap_read(ctx, dup_loc));
    heap_set(ctx, dup_loc, val);

    if (term_tag(val) == TAG_SUP) {
        u32 sup_label = term_ext(val);
        u64 sup_loc = term_val(val);
        ctx->itrs++;

        if (dup_label == sup_label) {
            // ANNIHILATION: same label — project directly
            // DP0 returns slot 0, substitutes slot 1 for the other projection
            // DP1 returns slot 1, substitutes slot 0 for the other projection
            Term tm0 = heap_read(ctx, sup_loc + 0);
            Term tm1 = heap_read(ctx, sup_loc + 1);
            if (dp_index == 0) {
                heap_set(ctx, dup_loc, tm1);  // other projection gets tm1
                t = tm0;
            } else {
                heap_set(ctx, dup_loc, tm0);  // other projection gets tm0
                t = tm1;
            }
            goto inet_step;
        } else {
            // COMMUTATION: different label — pass through, preserve both labels
            Term a = heap_read(ctx, sup_loc + 0);
            Term b = heap_read(ctx, sup_loc + 1);
            // Create 4 new DUP projections with the ORIGINAL dup_label
            // Reuse sup_loc for du0, alloc new for du1
            u64 du0 = sup_loc;   // reuse (a already there)
            u64 du1 = heap_alloc(ctx, 1);
            heap_set(ctx, du1, b);
            // Create 2 new SUPs with the ORIGINAL sup_label
            u64 su0 = heap_alloc(ctx, 2);
            u64 su1 = heap_alloc(ctx, 2);
            heap_set(ctx, su0 + 0, term_new(TAG_DP0, dup_label, du0));
            heap_set(ctx, su0 + 1, term_new(TAG_DP0, dup_label, du1));
            heap_set(ctx, su1 + 0, term_new(TAG_DP1, dup_label, du0));
            heap_set(ctx, su1 + 1, term_new(TAG_DP1, dup_label, du1));
            Term new_sup0 = term_new(TAG_SUP, sup_label, su0);
            Term new_sup1 = term_new(TAG_SUP, sup_label, su1);
            if (dp_index == 0) {
                heap_set(ctx, dup_loc, new_sup1);  // other projection
                t = new_sup0;
            } else {
                heap_set(ctx, dup_loc, new_sup0);
                t = new_sup1;
            }
            goto inet_step;
        }
    }
    // DUP ⊳ LAM: commutation — duplicate lambda, SUP label = dup_label
    if (term_tag(val) == TAG_LAM) {
        u64 lam_loc = term_val(val);
        Term body = heap_read(ctx, lam_loc + 1);
        // Clone body with dup_label
        Term body0 = term_new(TAG_DP0, dup_label, heap_alloc_set(ctx, body));
        Term body1 = term_new(TAG_DP1, dup_label, term_val(body0)); // same loc
        // Actually: simpler to use thvm_dup
        // But need single-slot sharing like HVM4's term_clone_at
        Term var0, var1;
        u64 bdup_loc = heap_alloc(ctx, 1);
        heap_set(ctx, bdup_loc, body);
        Term lam0 = thvm_lam(ctx, &var0, term_new(TAG_DP0, dup_label, bdup_loc));
        Term lam1 = thvm_lam(ctx, &var1, term_new(TAG_DP1, dup_label, bdup_loc));
        // Original var gets SUP of new vars (with dup_label, not fresh)
        heap_set(ctx, lam_loc, term_new(TAG_SUP, dup_label, /* loc of {var0,var1} */));
        // ... (full impl needs careful heap management)
        ctx->itrs++;
        t = (dp_index == 0) ? lam0 : lam1;
        goto inet_step;
    }
    // DUP ⊳ atoms: copy (both projections get same value)
    if (term_tag(val) == TAG_TEN) return val;
    if (term_tag(val) == TAG_ERA) return val;
    if (term_tag(val) == TAG_NUM) return val;
    // DUP ⊳ TOP/CTR/OP2: generic node duplication (DUP-NOD)
    // Clone each child with dup_label, create two copies of the node
    // (see Phase 3 for TOP-specific handling)
    return t;  // stuck — wait for val to reduce further
}
```

### 1d. DUP-NOD: generic compound node duplication

Following HVM4's `wnf_dup_nod`, handle all compound nodes uniformly:

```c
// Generic duplication for any compound node (TOP, CTR, OP2)
u32 arity = node_arity(val);
if (arity > 0) {
    u64 val_loc = term_val(val);
    u64 r0 = heap_alloc(ctx, arity);
    u64 r1 = heap_alloc(ctx, arity);
    for (u32 i = 0; i < arity; i++) {
        Term child = heap_read(ctx, val_loc + i);
        u64 dup_child = heap_alloc(ctx, 1);
        heap_set(ctx, dup_child, child);
        heap_set(ctx, r0 + i, term_new(TAG_DP0, dup_label, dup_child));
        heap_set(ctx, r1 + i, term_new(TAG_DP1, dup_label, dup_child));
    }
    Term n0 = term_new(term_tag(val), term_ext(val), r0);
    Term n1 = term_new(term_tag(val), term_ext(val), r1);
    if (dp_index == 0) { heap_set(ctx, dup_loc, n1); t = n0; }
    else               { heap_set(ctx, dup_loc, n0); t = n1; }
    ctx->itrs++;
    goto inet_step;
}
```

This handles DUP-TOP (duplicate lazy tensor op), DUP-OP2, DUP-CTR all in one rule.

### 2a. APP-SUP (fun position)

### 2b. APP-SUP (arg position — NOT a separate rule in HVM4)

In HVM4, there is **no separate arg-position APP-SUP rule**. The standard APP-LAM
fires first (beta reduction), and if the body then encounters the SUP through the
bound variable, DUP-SUP handles it. The arg-position rule from the previous session
was an optimization to avoid the Cartesian product from non-linear variable use.

HVM4's approach: `(λx. x+x) &L{3,7}` → beta → `&L{3,7} + &L{3,7}` → the `+` sees
SUP on left → OP2-SUP → `&L{3+DUP, 7+DUP}` → DUP-SUP annihilates (same label L) →
`&L{3+3, 7+7}` = `&L{6, 14}`. ✓

This works because the DUP inserted by OP2-SUP uses the same label L, so when it hits
the same SUP (now in the second operand position), it annihilates correctly.

**Decision**: Follow HVM4 — no arg-position APP-SUP. The standard beta + DUP-SUP
mechanism handles non-linear variables correctly via label matching.

### 2c. OP2-SUP distribution

Left operand is SUP — DUP right operand with SUP's label:
```c
if (term_tag(x) == TAG_SUP) {
    u32 lab = term_ext(x);
    u64 sup_loc = term_val(x);
    Term x0 = heap_read(ctx, sup_loc + 0);
    Term x1 = heap_read(ctx, sup_loc + 1);
    // Clone y with SUP's label
    u64 dup_loc = heap_alloc(ctx, 1);
    heap_set(ctx, dup_loc, y);
    Term y0 = term_new(TAG_DP0, lab, dup_loc);
    Term y1 = term_new(TAG_DP1, lab, dup_loc);
    ctx->itrs++;
    t = thvm_sup(ctx, lab,
        thvm_op2(ctx, opr, x0, y0),
        thvm_op2(ctx, opr, x1, y1));
    goto inet_step;
}
```

Right operand is SUP — no DUP needed (left operand already reduced to atom):
```c
if (term_tag(y) == TAG_SUP) {
    u32 lab = term_ext(y);
    u64 sup_loc = term_val(y);
    Term y0 = heap_read(ctx, sup_loc + 0);
    Term y1 = heap_read(ctx, sup_loc + 1);
    ctx->itrs++;
    // x is already a NUM (atom), just reuse — HVM4 doesn't DUP atoms
    t = thvm_sup(ctx, lab,
        thvm_op2(ctx, opr, x, y0),
        thvm_op2(ctx, opr, x, y1));
    goto inet_step;
}
```

HVM4 note: OP2 has two phases (OPX reduces left, OPY reduces right). When OPX sees
a SUP on left, it distributes. When OPY sees a SUP on right (left already NUM), the
left atom is copied directly (atoms are free to duplicate).

Not needed yet in TinyHVM (no MAT/SWI), but worth noting for future constructors.

### 3a. When a lazy tensor op encounters SUP

### 3c. Shape constraint as early pruning

Before distributing, optionally check ShapeTracker for both branches:

```c
if (term_tag(a0) == TAG_TEN && term_tag(a1) == TAG_TEN) {
    Shape s0 = ctx->tensors[term_val(a0)].view.shape;
    Shape s1 = ctx->tensors[term_val(a1)].view.shape;

```

This is the first "type-directed" pruning — shapes ARE types.

### 3d. FUSED-SUP: fusion boundary at SUP

When `materialize_walk` encounters TAG_SUP during tree traversal:
- **Stop fusion** at the SUP boundary
- Treat each SUP branch as an independent leaf
- Each branch gets its own fused kernel

This is HVM4's Strategy A. Strategy B (fusing across branches) would require codegen
to emit two output buffers from one kernel — complex, future work.

## Phase 4: GRAD-SUP Interaction

### 4a. Gradient through superposition

When GRAD walks provenance and hits a result that came from a SUP distribution:

```
Forward: TOP(ADD, &L{a,b}, c) distributed to → &L{ADD(a,c0), ADD(b,c1)}
         Each branch materializes independently with its own provenance.
```

GRAD follows provenance per-branch. No special SUP handling needed in the GRAD handler
itself — each materialized tensor has its own `creator_op` and `src_ids`.

### 4b. What if GRAD's target tensor `y` is itself a SUP?

This shouldn't happen in practice: GRAD fires after reducing `y` to TAG_TEN.
If a SUP survives to GRAD entry, it means the forward pass didn't fully distribute.
Handle defensively:

```c
if (term_tag(y_term) == TAG_SUP) {
    // Distribute: GRAD each branch independently
    u32 lab = term_ext(y_term);
    u64 sup_loc = term_val(y_term);
    Term y0 = heap_read(ctx, sup_loc + 0);
    Term y1 = heap_read(ctx, sup_loc + 1);
    u64 gy_dup = heap_alloc(ctx, 1);
    heap_set(ctx, gy_dup, gy);
    Term gy0 = term_new(TAG_DP0, lab, gy_dup);
    Term gy1 = term_new(TAG_DP1, lab, gy_dup);
    t = thvm_sup(ctx, lab,
        GRAD3(y0, gy0, x),
        GRAD3(y1, gy1, x));
    goto inet_step;
}
```

### 4c. Architecture search with gradients

With labeled SUP/DUP, you can superpose different model architectures and train them
simultaneously. Each architecture gets correct gradients because:

1. TOP-SUP distributes ops across branches
2. Each branch materializes with its own provenance
3. GRAD follows per-branch provenance
4. ASSIGN accumulates per-branch gradients into per-branch parameter slots

The label ensures that when parameters are shared across architectures (same label
for shared params, different labels for architecture-specific choices), gradients
accumulate correctly.

## Phase 5: Collapse Function

### 5a. Implementation strategy

TinyHVM's collapse needs two phases:

1. **`thvm_collapse_step(ctx, term)`**: Reduce to WHNF. If result is SUP, lift it to
   the root. If result is a compound node whose child is SUP, lift the child SUP.
   Return the outermost SUP.

2. **`thvm_collapse(ctx, term)`**: Iterate `collapse_step`, collecting all branches.
   Use a priority queue keyed by label for breadth-first exploration.

### 5b. Priority queue and INC

HVM4 uses INC nodes to control collapse ordering. A term wrapped in INC gets lower
priority in the queue → explored later. This enables search strategies:

```wolfram
(* Prefer simpler programs: wrap complex branches in INC *)
TSup[label, simple_program, TInc[complex_program]]
```

### 5c. Label-aware bind (for WL interface)

The WL-level Collapse can be implemented purely in Wolfram:

```wolfram
TCollapse[term_] := Module[{whnf = TReduce[term]},
  If[TTag[whnf] === "SUP",
    {lab, a, b} = TSupFields[whnf];
    Join[TCollapse[a], TCollapse[b]],
    {whnf}
  ]
]
```

For pairwise semantics, the more complex path-tracking bind is needed.
Start with simple DFS flattening, add path-tracking as needed.

## Phase 6: Types via ICC Bridge/Annotation

### 6a. Bridge and Annotation nodes

```c
#define TAG_BRI 14   // Bridge: θx. term (dual of lambda)
#define TAG_ANN 15   // Annotation: {term : type}
```

Heap layout identical to LAM/APP:
- BRI: `heap[loc] = var_slot, heap[loc+1] = body`
- ANN: `heap[loc] = term, heap[loc+1] = type`

### 6b. ICC type encodings

```
Fun A B = θf. λx. {(f {x:A}) : B}           -- simple function type
All A B = θf. λx. {(f {x:A}) : (B x)}       -- dependent function (Pi)
Ind A B = θf. λx. {(f {x:A}) : (B f x)}     -- inductive/self type
Sig A B = θp. {(p {p.0:A} {p.1:(B p.0)})}   -- dependent pair (Sigma)
```

### 6c. Type checking = reduction

When `{term : type}` reduces, the annotation checks that `term` conforms to `type`.
For tensor types, this means shape/dtype checking. For function types, this means
checking domain/codomain. Failed checks reduce to ERA → branch pruned.

### 6d. Practical staging

Before full ICC, implement lightweight type guards using existing IC:

```wolfram
(* Shape guard: pass through if shape matches, ERA otherwise *)
TShapeGuard[t_, shape_] :=
  TIfZ[TShapeEq[TShape[t], shape], t, TEra[]]

(* Dtype guard *)
TDtypeGuard[t_, dtype_] :=
  TIfZ[TDtypeEq[TDtype[t], dtype], t, TEra[]]
```

Full ICC (TAG_BRI, TAG_ANN) added later when the guard approach hits limits.

## Phase 7: DSU/DDU — Dynamic Labels (future)

For computed search spaces where labels depend on data:

```c
#define TAG_DSU 16   // Dynamic SUP: &(label_expr){a, b}
#define TAG_DDU 17   // Dynamic DUP: !&(label_expr){x} = val; bod
```

Reduce `label_expr` to NUM, then create normal SUP/DUP. This enables:

```wolfram
(* Generate search space programmatically *)
MakeSearch[n_] := Fold[
  TSup[TNum[#2], ...] &,    (* each level gets label = its index *)
  candidates,
  Range[n]
]
```

## How Types Help TOP/GRAD/FUSED (summary)

### TOP + types
- ShapeTracker IS a dependent type system — eagerly computes output shapes
- Wire ShapeTracker into TOP-SUP distribution for early pruning
- Invalid shape combinations → ERA before any GPU work

### GRAD + types
- `requires_grad` IS a linearity annotation (Differentiable vs Frozen)
- With labeled SUP: each architecture branch has independent provenance
- Dead-branch skip in BIN_GRAD = type-directed gradient routing
- ICC annotations could make differentiability a first-class type

### FUSED + types
- `is_elementwise()` / `is_binary()` = ad-hoc type queries on UOP codes
- Fusion rewrite rules = type-directed pattern matching on op categories
- SUP boundary = fusion type boundary (can't fuse across independent dimensions)
- Shape types let fuser verify both SUP branches produce compatible output shapes

### Key insight: TinyHVM already has three implicit type systems

1. **ShapeTracker** → dependent shape types
2. **requires_grad + creator_op** → linear/differentiable types
3. **is_elementwise/is_binary** → operation category types

ICC's contribution is making these explicit and composable, so SupGen can enumerate
and constrain across all three dimensions simultaneously.

## Implementation Order

1. **Phase 1** — Labeled SUP/DUP + DUP-SUP annihilation/commutation + DUP-NOD
2. **Phase 2** — APP-SUP, OP2-SUP distribution (following HVM4 exactly)
3. **Phase 3** — TOP-SUP distribution + shape pruning
4. **Phase 5** — Collapse function (simple DFS first, PQ later)
5. **Phase 4** — GRAD-SUP (defensive, mostly gets it free from TOP-SUP distribution)
6. **Phase 6** — Type guards via TIfZ (pragmatic, no new tags)
7. **Phase 7** — DSU/DDU, INC, full ICC (as needed)

Phases 1-2 are pure interaction calculus (no tensor changes).
Phases 3-5 connect SUP to the tensor + collapse system.
Phases 6-7 add type-theoretic and dynamic features.
